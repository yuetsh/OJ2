# OJ2 设计文档：「数据分析」—— 教 Python 第三方库的新板块

日期：2026-11-12
状态：**四段都已实施（2026-11-12），本机跑通，还没上线。** 下面每一条都是和用户一件一件拍过板的，
「拍板」一栏写的是当时的选择。代码在：运行器 `docker/lab/`；后端 `apps/api/src/routes/lab.ts`（学生 + 进度页）、
`routes/admin/lab.ts`（出题）、`services/lab.ts`；前端 `apps/web/src/oj/lab/`（列表、一节、全班进度）、

## 1. 为什么要一个新板块

要给学生上 Python 第三方库（pandas、matplotlib 这一类）。OJ 的形状是「给输入、比输出、判对错」，
套不上这类课：一节课的节奏是老师给一份数据，学生一步一步调库、看表格和图，结果是表格和图片，
不是一行 stdout。所以**不复用 OJ 也不复用自学**，另起一个板块，和它们并列。

界面上叫 **「数据分析」**；代码、表名、路由一律用 `lab`，和界面叫法脱钩，改名不牵连代码。

## 3. 一节「数据分析」长什么样

```
数据分析：用 pandas 分析班级成绩
  ├─ 素材：成绩.xlsx（老师上传；页面上能直接点开看表）
  ├─ 第 1 步：读进来，看前 5 行        [代码] [运行] → 表格        （A 不检查）
  ├─ 第 2 步：算每科平均分              [代码] [运行] → 表格  ✓     （B 比 avg）
  ├─ 第 3 步：画柱状图                  [代码] [运行] → 图片  ✓     （B 比图）
  └─ 第 4 步（可选，开放步骤）：选一科画一张你觉得最能说明问题的图，写一句你看出了什么
```

每一步：说明（Markdown）、初始代码、检查方式、（B 类）参考代码与要比的变量名、（C 类）检查脚本。

运行结果是**富输出**：print 的文本、DataFrame 渲染成表、matplotlib 图片。

### 3.1 三种检查

- **A 不检查**：跑过、没报错就算完成。给「读进来看看」这类演示步骤用。
- **B 对照参考答案（默认）**：老师写参考代码，指定比哪几个变量；老师的和学生的各跑一遍再比。
  - DataFrame / Series：形状、列名（索引）、数值，小数允许误差；
  - 数字、字符串、列表：直接比；
  - 图：比「画了什么」——从 matplotlib 的 figure 对象读柱子 / 折线的数值、标题、坐标轴标签，**不比像素**。
  - 没过时自动说清差在哪，例如「avg 里『数学』这一项：你的是 65.3，应该是 67.1」。
- **C 自定义检查脚本**：老师写 `assert 条件, '给学生的提示'`，在学生代码跑完的同一个命名空间里执行。
  给「答案不唯一、但要满足某条件」的步骤用；失败提示同时起「卡住时给提示」的作用，不另做提示功能。

**开放步骤**：不检查，提交即完成；只给老师看（第一版不做互相看）。

## 4. 执行：一个独立的 `lab` 容器

和判题机（go-judge，`oj2-judge-3`）**完全分开**：库升级、出问题都不碰判题。

```
lab 容器（Python 3.13，和判题镜像同一大版本）
 └─ 常驻母进程：启动时 import 好 pandas / numpy / matplotlib(Agg) / seaborn / jieba(含词典) / wordcloud，
    画一张图预热字体
      ├─ 某学生点「运行第 k 步」→ fork 子进程
      │     → 新建临时目录，放进本实验的素材
      │     → 在同一个命名空间里依次执行第 1…k 步的代码
      │     → 收集 stdout、表格、图片；跑检查（B / C）
      │     → 结果回传，删临时目录，退出
      └─ …
```

- **重跑前面所有步骤**拿到变量，而不是常驻进程：没有「状态」可言（不存在「我刚才跑没跑过第 1 步」），
  服务器也不必为每个学生留内存。前面某一步报错时，报在那一步上。
- **隔离**：断网；子进程限 CPU 时间、内存、输出大小、图片数量与尺寸；每次独立临时目录；容器只读。
  具体数值实施时实测着定。
- **中文字体**：镜像装中文字体（原型用文泉驿微米黑），matplotlib 默认就用它，`axes.unicode_minus = False`。
- 部署只加在 `compose.debian.yml`（机房那套还没部署，见 memory）和 `compose.dev.yml`。

### 4.1 原型实测（2026-11-12，开发机，`--cpus=2 --network=none`）

场景：读 40 行 xlsx → 求四科平均 → 画带中文标题的柱状图存 png。

| 场景 | 结果 |
|---|---|
| 不预热，每次重新 import（单次） | 约 0.7 s 墙钟 / 0.75–0.9 s CPU |
| 预热 + fork，1 人 | 0.08 s |
| 预热 + fork，10 人同时 | 最后一个 0.41 s |
| 预热 + fork，40 人同时 | 中位 1.8 s，最后一个 2.1 s |
| 母进程常驻内存 | 114 MB |
| 母进程启动预热 | 约 0.7 s（只在容器启动时） |
| 一张图 | 约 14 KB |

不预热时 40 人同时约 40 × 0.8 ÷ 2 ≈ 16 s。开发机单核比服务器快，服务器上估计 40 人同时、
最后一个等 3–5 s。**上线前在服务器上用同一个原型再测一次。** 原型不进仓库（scratchpad 里），
实施时照着重写即可：`python:3.13-slim` + `fonts-wqy-microhei` + pip 装白名单。

## 5. 数据

新表，和 `problem` / 提交不混：

| 表 | 内容 |
|---|---|
| `lab` | 标题、说明、可见性、创建者、时间 |
| `lab_step` | 所属 lab、序号、类型（普通 / 开放）、说明、初始代码、检查方式（A/B/C）、参考代码、要比的变量、检查脚本 |
| `lab_asset` | 所属 lab、文件名、文件（存 `DATA_DIR` 下） |
| `lab_progress` | 学生 × 步骤：最新代码、最近一次运行结果摘要、**首次通过时间**；开放步骤存提交的文字 + 图 |

- 代码**只存最新一版**，运行时保存、停止输入几秒后自动保存；不留每次运行的历史（和 OJ 的提交不同，运行只是试）。
- 时间列照全仓规矩 `timestamptz`，存 UTC。
- 素材是老师上传的，可能含学生真名；系统不做脱敏。

## 6. 页面

**设计稿已定（2026-11-12）**：「重设计」画布 https://claude.ai/artifact/QN9uG3qRiF9CQpLiay7jZG
的「数据分析」页，三张画板 `LabStudent` / `LabProgress` / `LabEdit`。**画布管样子，本文管规则。**

**学生**（`LabStudent`）：顶栏「数据分析」放在「自学」后面 → 列表 → 一节：上面素材（直接显示前 5 行，
可看全部、下载），下面步骤**一页往下排到底**（拍板：不做一次一步，也不自动折叠做过的步骤）。
每步代码区 + 运行 + 结果 + 检查结论；通过后该步出现「看老师的写法」。手机端能看能改，但以电脑为主。

**老师 · 全班进度**（`LabProgress`，路由 `/lab/:id/progress`，10 秒刷新一次）：放在**前台**，老师上课不用进后台。顶上一条总览（全部做对 /
卡在第几步 / 还没开始），左边按「卡在哪一步」分组，同一步再按**没过的那条检查**细分并列名字；点名字右边
看该生每步的时间、运行次数、代码和图。看别人的代码只给老师（沿用现有规矩）。

**老师 · 出题**（`LabEdit`）：后台「教学内容」组最后一项。照编程题出题页的左写右看：
标题和说明、素材、步骤（收起的显示检查方式和是否跑通，展开的可编辑），B 类「比什么」可选「画出来的图」
或变量名，图再勾比数值 / 标题 / 坐标轴文字；「试跑这一步」用答案把前面各步连这一步跑一遍。
